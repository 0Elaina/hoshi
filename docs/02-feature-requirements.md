# Hoshi 功能需求清单

本文档定义 Hoshi 面向真实用户的多角色 AI 聊天陪伴 Agent 平台功能范围与能力边界，作为后续模块拆分、数据建模与接口设计的基线。

## 1. 账号与权限域

### 1.1 普通用户账号
- **注册与登录**：普通用户支持自主注册、登录、刷新会话与登出，拥有独立会话 TTL 与登录限流保护。
- **个人资料与偏好**：维护用户昵称、头像、基础个人偏好及跨角色共享的陪伴交互设置（如主动关怀开关、免打扰时段）。

### 1.2 管理员账号
- **独立后台认证**：管理员账号与普通用户账号在类型与角色上隔离，由维护者通过命令行脚本与数据库操作开通，登录管理端后执行平台治理。

## 2. 用户端陪伴对话域（Web）

### 2.1 AI 角色管理与发现
- **角色广场**：浏览平台预设的官方 AI 角色，按标签或定位筛选并开启陪伴对话。
- **自定义角色**：用户创建、编辑与归档个人专属 AI 角色，配置角色名称、头像、性格人设、说话风格、开场白与世界观设定集。

### 2.2 实时陪伴对话
- **多会话管理**：用户与同一角色或不同角色之间支持建立、切换、重命名与归档对话线程，查看历史消息记录。
- **流式交互体验**：通过 SSE 实时接收 AI 角色的思考状态、工具调用提示与逐字流式回复，支持主动中断生成与重新生成。
- **可扩展消息载体**：消息渲染层与数据结构预留多模态内容块（文本、图片、语音等），当前优先承载富文本对话，后续平滑接入语音与视觉交互。

### 2.3 记忆、关系与主动关怀
- **关系与情绪感知**：直观呈现当前与角色的关系阶段、好感度及角色实时情绪状态。
- **长期记忆可视化与管理**：用户可查看角色记住的重要事实与共同经历，支持手动补充、修正或遗忘特定记忆条目。
- **主动关怀接收**：用户在离线回访或在线状态下，可接收来自 AI 角色的定时问候、事件跟进等主动消息，并直接回复延续上下文。

## 3. AI 陪伴 Agent 核心能力域

- **人设一致性控制**：基于分层 Prompt 注入角色性格、语言习惯与安全边界，保证长周期对话不发生人设漂移。
- **双层记忆体系**：LangGraph Checkpointer 持久化短期对话状态快照；Qdrant 存储并检索长期情景记忆、用户事实与角色设定集，支持基于时间衰减与相关性的动态召回。
- **情绪与关系状态机**：在对话流转中动态评估用户意图与交互反馈，更新角色情绪及关系状态，并反向影响回复语气与主动行为策略。
- **可扩展工具调用**：通过统一工具注册机制支持时间感知、联网搜索、日程/提醒等外部能力，工具按角色能力配置启用。
- **主动关怀调度**：结合用户最后活跃时间、记忆事件与防打扰冷却策略，触发后台主动问候生成与推送。

## 4. 平台管理端域（Admin）

- **用户治理**：分页检索平台普通用户，支持查看账号详情、调整状态（启用/禁用）与管理其活跃会话。
- **官方角色与设定集维护**：创建、发布、下线平台预设 AI 角色，维护角色基础 Prompt 模板与向量知识库设定集。
- **模型与提供方配置**：配置 OpenAI 兼容模型提供方（API 基址、密钥引用、模型标识），按用途（主对话、记忆提炼、Embedding 及后续多模态模型）分配默认路由与参数。
- **运行与调用审计**：查看会话活跃概览、模型调用耗时与异常记录、工具调用及主动任务执行状态。
