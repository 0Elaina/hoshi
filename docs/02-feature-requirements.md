# Hoshi 功能需求

本文记录已经确认的业务需求。具体功能在讨论确定后补充到对应内容中，功能范围随开发演进。

## 内容范围

- 以音乐为核心，面向用户提供音乐浏览与在线播放能力。
- 平台自主维护曲库，由站方通过管理端维护歌曲、歌手、专辑及关联音频、封面。
- 用户端使用平台维护的音乐数据与资源提供服务。

## 产品参考原则

以网易云音乐作为功能组织与交互的产品参考，结合本项目的自主曲库和网站使用方式设计具体功能。

具体功能讨论时，依据参考产品的实际页面确认信息、操作流程和交互表现，再确定网站中的实现要求。参考产品的某项能力在纳入本项目需求前，须结合本项目需求与个人维护成本进行讨论确认。

产品定位、参考来源及工程约定见[项目概览](01-project-overview.md)。

## 站方维护

站方能够通过管理端维护歌曲、歌手、专辑及关联音频、封面，为用户端提供实际可用的音乐内容。

对应数据应能够完成录入、关联、修改及必要的可用性管理，使用户端所依赖的数据和资源能够持续维护。具体字段、关联关系、操作、状态规则和权限在对应功能设计时确定。

## 音乐浏览与播放

用户能够通过用户端浏览平台曲库并在线播放可用音乐。具体页面、浏览方式和播放交互在对应功能设计时确定。

## 两端职责

| 端 | 已确认职责 |
| --- | --- |
| 管理端 | 为站方提供歌曲、歌手、专辑及关联音频、封面的维护入口，维护音乐数据、资源及其可用性 |
| 用户端 | 使用平台维护的曲库，面向用户提供音乐浏览与在线播放 |

## 开发顺序与质量要求

先建设管理端及其依赖的后端能力，再围绕能够被实际维护的数据开发用户端功能。进入对应用户端功能开发前，其依赖的数据与资源应已能够在管理端完成录入、关联、修改及必要的可用性管理。

具体功能按业务依赖逐步推进，每个开发单元落实必要的职责划分、数据契约、校验、权限控制、数据一致性和错误反馈。阶段划分只安排工作顺序，工程质量要求保持一致。
